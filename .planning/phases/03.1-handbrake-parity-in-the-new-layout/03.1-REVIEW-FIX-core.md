## Fixed Issues

### CR-01: A closed-caption track marked Default crashes the encode
**Commit:** 30d177d
**Files:** `Engine/SubtitleTrackPlanner.swift`, `Engine/PipelineFactory+Subtitles.swift`, `Engine/PipelineFactory.swift`
**Applied fix:** `explicitEntries` sets `isDefault` only for `.subtitle` tracks. `subtitlePumps` passes a default only when it is one of the grouped inputs. `groupAlternates` also ignores a default that isn't in `inputs`, so `AVAssetWriterInputGroup` can't raise.
**Tests:** `closedCaptionIsNeverDefault`, `groupIgnoresDefaultOutsideInputs`.

### CR-02: The audio language filter never matches typical MP4/MOV sources
**Commit:** 7a56cf2
**Files:** `Engine/PipelineFactory+Audio.swift`
**Applied fix:** The planner uses `extendedLanguageTag ?? languageCode`. The audio writer input now also copies `languageCode`.
**Tests:** `languageSelectionUsesISOCode` (integration, with a source that has only the `mdhd` code).

### WR-01: HandBrake ISO 639-2/B codes never match
**Commit:** d064bac
**Files:** `Models/LanguageFilter.swift`
**Applied fix:** A 20-entry B→T table (fre→fra, ger→deu, chi→zho, …) is applied before the Locale lookup.
**Tests:** `bibliographicCodesMatch` (7 cases, both directions).

### WR-02: HandBrake `copy:<codec>` becomes an unconditional passthrough
**Commit:** 5474811
**Files:** `Models/EncodeSettings.swift`, `Models/AudioOptions.swift`, `Models/HandBrakePresets+Audio.swift`, `Engine/PipelineFactory+Audio.swift`
**Applied fix:** A new optional `passthruOnly: PassthruCodec?` on `AudioEncoding` and on `AudioOptions` (for the main version). Both are decoded with `decodeIfPresent`, and nil keeps the old behaviour (D-05). `copy:X` now maps to `.autoPassthru` with `passthruOnly = X`, and the pipeline narrows the allowed set to `[X]`, so other codecs use the fallback encoder. An unknown `copy:X` adds an import note.
**Tests:** `copyCodecIsConditionalPassthru` (import), `passthruOnlyCopiesJustThatCodec` (integration).
**Note for UI:** the field is model-only. No UI exposes it yet, and changing the codec in the UI leaves it set but inert unless the codec is Auto Passthru.

### WR-03: Explicit per-track lists override "No Audio" / "None", and the estimates
**Commit:** 36eacbc
**Files:** `Engine/AudioTrackPlanner.swift`, `Engine/SubtitleTrackPlanner.swift`, `Models/Estimates.swift`, `Models/SizePrediction.swift`, `Engine/MediaInspector.swift`
**Applied fix:** `AudioTrackPlanner.plan` returns `[]` when `audioCodec == .none` or `audioTracks == .none`. The subtitle planner keeps no source tracks when `subtitles == .none`; external files behave as before. Audio estimates and the 160 kbit/s fallback now go through `OutputEstimate.audioJobs`, which is the `AudioTrackPlanner` plan (explicit list, language filter, extra-first-only). `MediaInspector` reports `languageCode` when there is no extended tag, so estimates and UI languages see ISO-coded tracks.
**Tests:** `noAudioOverridesExplicitList`, `noneOverridesExplicitList`, `explicitTrackListDrivesAudioSize`, `languageFilterDrivesAudioSize`.

### WR-04: The filtered path renders anamorphic sources at storage width
**Commit:** 9ea1932
**Files:** `Engine/FrameFilter.swift`
**Applied fix:** `FrameFilter.toSourceSize` scales the decoded frame from its real `image.extent` (storage size) to the instruction's `sourceSize` (naturalSize, which is the display size for PAR-tagged tracks). This runs after the filters and before the geometry transform. It is an identity when the sizes match.
**Tests:** `filteredAnamorphicSourceFillsTheFrame`. It sends a 480×360 clip with 4:3 PAR through `grayscale` and checks the right-edge column luma of the 640×360 output. Before the fix it was ~0 (canvas); after the fix it is the picture.

### WR-05: AudioGain assumes interleaved Float32 and silently drops the gain on failure
**Commit:** d7be4b4
**Files:** `Engine/AudioGain.swift`, `Engine/SamplePump.swift`, `Engine/TranscodeEngine.swift`
**Applied fix:** `apply` checks the ASBD (LPCM, 32-bit float, packed/interleaved, native endian) and that the byte length equals `sampleCount × channels × 4`. `SampleTransform` may now throw. The pump records the error in `failure`, sets the shared cancel flag and stops, and the engine rethrows that error. A gain failure therefore fails the job instead of producing audio that is gained in some packets and not in others. The force unwraps in AudioGain were removed as part of this change.
**Tests:** `gainRejectsOtherPCMLayouts`, `failingTransformStopsThePumpAndRecordsTheError`. The seam tests were updated for the throwing `filtered`.

### WR-06: MKV output gains ACTOR (and iTunes DATE_RELEASED) tags with default settings
**Commit:** 78a4a39
**Files:** `Engine/Matroska/MatroskaMetadata.swift`, `Engine/Matroska/MatroskaRemuxer.swift`, `Engine/TranscodeEngine.swift`
**Applied fix:** `MatroskaRemuxer` takes the job's `MetadataTags`. ACTOR, DIRECTOR, COMMENT, GENRE and SYNOPSIS now come only from those user tags, never from source metadata. DATE_RELEASED reads only the common creation date, as in 711f915. With default settings, MKV output has the same tag set as before (D-05).
**Tests:** `defaultSettingsAddNoNewTags`, which uses a source with QT artist, director, comment and genre and expects only TITLE, ARTIST, DATE_RELEASED and DESCRIPTION. The existing user-tag MKV tests still pass.

### WR-07: Align A/V Start only works when the source has a leading empty edit
**Commit:** 3c6c7a0
**Files:** `Engine/AVAlignment.swift`
**Applied fix:** The first frame time is the later of two values: the start of the first non-empty edit, and the earliest PTS among the first 16 samples read by a short-lived `AVAssetReaderTrackOutput(outputSettings: nil)`. Those PTS values are already on the movie timeline. This only runs when `alignAVStart` is on.
**Tests:** `sampleOffsetLeadInIsAligned` and `alignedEncodeOfSampleOffsetSourceDropsTheLeadIn`. Both use an `AVMutableMovie` fixture whose video samples present 0.5 s after they decode, with a single edit from media time 0 and no empty edit.

### WR-08: "Forced only" drops whole tracks, and `SubtitlePlanEntry.forced` is unused
**Commit:** e50c0be
**Files:** `Engine/SubtitleTrackPlanner.swift`, `Engine/PipelineFactory+Subtitles.swift`, new `Engine/ForcedSubtitles.swift`
**Applied fix:** This implements HandBrake's meaning. "Forced only" on an ordinary tx3g track keeps the track. A sample transform keeps cues that carry a `frcd` sample-modifier box and replaces the rest with empty cues of the same timing. Every sample is re-described with a copy of the source format that has `kCMTextDisplayFlag_allSubtitlesForced`, so the MOV/MKV output is flagged forced. A track with no forced cue is left out after a quick pre-scan, as before. Tracks that are already all-forced are copied unchanged. Closed captions and non-tx3g formats with "Forced only" are skipped. `entry.forced` now drives this behaviour.
**Tests:** `forcedOnlyKeepsTextTracksForCueFiltering`, `forcedBoxIsFoundAfterTheText`, and `forcedOnlyKeepsJustTheForcedCues`. The last is an integration test with a mixed track whose output keeps only "Forced" and reports `forcedOnly == true`.

### IN-02: Function-size rule (<50 lines) exceeded

No function in HyperVideoCore is now 50 lines or longer, and every file is under 400 lines. The StressClip audio-input setup moved into a helper.

### IN-04: The peak limiter gives well under the peak for some source rates
**Commit:** 6b1f58f
**Files:** `Engine/PeakRateLimiter.swift`
**Applied fix:** Frames are admitted against an ideal `1/peak` slot grid. A pause in the source resets the grid so that no burst follows. Results: 50→30 gives ~30 fps (was 25), 120→50 gives ~50 (was 40), and 60→24 gives ~24.
**Tests:** `peakLimiterStaysNearThePeak` (3 cases) and `peakLimiterDoesNotBankTimeAcrossPauses`. The existing limiter tests still pass.

### IN-05: ChapterCSV.format doesn't round-trip titles with newlines; TimedText cut can split a scalar
**Commit:** c8733ab
**Files:** `Models/ChapterCSV.swift`, `Engine/TimedText.swift`
**Applied fix:** Line breaks (`\n`, `\r\n`, `\r`) inside a title become spaces. `TimedText.utf8Prefix` cuts over-long text at a character boundary.
**Tests:** `csvFormatFoldsLineBreaks`, `longCueIsCutOnACharacterBoundary`.

### IN-07: Baseline sent with frame reordering; Auto Passthru estimates ignore the fallback
**Commit:** 1d39eed
**Files:** `Engine/OutputSettingsBuilder.swift`, `Models/Estimates.swift`, `Models/AudioOptions.swift`
**Applied fix:** `AVVideoAllowFrameReorderingKey` is false whenever H.264 uses the Baseline profile. The estimates resolve Auto Passthru per track using `PassthruCodec.from(codecName:)`, the allowed set or `passthruOnly`, and container acceptance. A track that won't be copied is estimated at the fallback encoder's rate.
**Tests:** `baselineNeverReordersFrames`, `autoPassthruEstimatesTheFallbackWhenItWontCopy`.

## Skipped Issues

### IN-06: The 7.1 layout uses MPEG_7_1_B (front-centre pair), not a rear-surround 7.1
**File:** `Sources/HyperVideoCore/Engine/OutputSettingsBuilder+Audio.swift:72`
**Commit (investigation and pinning test):** 25e728c
**Reason:** No change is possible with Apple's AAC encoder. I tested every 8-channel tag with `AVAssetWriter.canApply` for 8-channel AAC:
- Accepted: MPEG_7_1_B, AAC_7_1 (the same order), AAC_7_1_B.
- Rejected: MPEG_7_1_A, MPEG_7_1_C, AAC_7_1_C, SMPTE_DTV, ITU_3_4_1.

I then encoded a tone on one channel at a time with AAC_7_1_B (C L R Ls Rs Rls Rrs LFE) and decoded the result. The C, L, R, Ls and Rs channels came through. **Rls, Rrs and LFE decoded as silence.** The encoder accepts the tag but drops the rear surrounds and LFE. Switching to AAC_7_1_B would therefore lose three channels, which is worse than folding the back surrounds into the side pair as MPEG_7_1_B does.
**What was done instead:** The layout stays MPEG_7_1_B, and a comment explains why. A new test, `surround71KeepsEverySourceChannelAudible`, feeds an uncompressed SMPTE 7.1 (MPEG_7_1_C) source with a tone on each side and back channel and checks that every one of them stays audible in the 8-channel output. It guards against a future switch to AAC_7_1_B. StressClip gained `layoutTag`, `onlyChannel` and `lpcm` options for this test.
**Possible follow-up:** use a per-codec layout (for example, ALAC may accept a rear 7.1 layout). That was not attempted because it is outside this finding.
