# Phase 03.1: Code Review Report (UI / app target)

**Reviewed:** 2026-10-23
**Depth:** standard (diff base 711f915)
**Files Reviewed:** 34
**Status:** issues_found

## Summary

I reviewed the 34 `Sources/HyperVideoConverter` files this phase touched: the new inline Video Settings panel, the eight HandBrake-style tabs, the track, chapter and tag helpers, and the preset merge logic.

Most per-video edits are wired correctly. `settingsBinding(for:)` captures the source id, so async writes such as chapter CSV import still land on the right video after the selection changes.

There are three CRITICAL problems:
1. The Summary tab edits the inspector's targets instead of the shown video when it is opened from the Advanced sheet.
2. Chapter title fields normalize every keystroke, which breaks typing.
3. Both Languages fields do the same.

Other problems:
- Some localized strings are shown verbatim.
- The Before → After summary ignores explicit track lists.
- A few view-local async and state patterns can go stale or crash.

Checks that found no problems:
- No file is over 400 lines, and no function is near 50 lines.
- No macOS 26-only API is used outside `Compat.swift`.
- No force-unwraps were added.
- The app has no sandbox entitlements, so URLs from `NSOpenPanel` and `NSSavePanel` need no security-scoped access.

## Critical Issues

### CR-01: Summary tab's Quality Profile and size estimate act on the inspector targets, not the video being edited

**File:** `Sources/HyperVideoConverter/Views/Tabs/SummarySettingsTab.swift:14-17`
**Issue:** `ProfileCards(selected: model.inspectorProfile) { model.applyProfile($0) }` and `EstimateCard()` read and write `model.inspectorTargetIDs`, not `settings`. That is the selected videos, or **all** videos when nothing is selected (`AppModel+Workspace.swift:29-32`, `93-110`).

The panel only appears with a single selection, but `AdvancedSettingsSheet` also uses `SettingsTabContent`. The sheet opens from a row's context menu (`WorkListView.swift:90`, `model.ui.advancedSourceID = source.id`) without changing the selection. So in the sheet for video B, with nothing selected, picking "Compact" rewrites every video in the list. It also changes `draftSettings` (`inspectsSelection == false`). The highlighted card and the size estimate describe other videos too.

Even in the inline panel for a lone, unselected video, `applyProfile` takes the `!inspectsSelection` path and also overwrites the draft used for videos added later.
**Fix:** Apply the profile through the per-video binding and compute the selection from `settings`:
```swift
let compress = QualityProfile.isCompressPreset(source.presetID) // pass presetID/source in
ProfileCards(selected: QualityProfile.matching(settings, compress: compress)) { profile in
    settings = settings.applyingProfile(profile.settings(compress: compress))
    model.update(sourceID) { $0.presetID = profile.presetID(compress: compress) }
}
// Replace EstimateCard() here with a per-video estimate (BeforeAfterSection already
// computes OutputEstimate.prediction(info:settings:)).
```

### CR-02: Chapter title field trims and resets on every keystroke, so you can't type spaces or clear the field

**File:** `Sources/HyperVideoConverter/Views/Tabs/ChaptersSettingsTab.swift:57-66`, `Sources/HyperVideoConverter/Stores/ChapterEditing.swift:20-29`
**Issue:** The `TextField` binding's setter runs `settingTitle`, which stores `text.trimmingCharacters(in: .whitespacesAndNewlines)`. It also stores `""` when the text equals the source title, and the getter turns `""` back into the source title.

Each keystroke round-trips through this. Typing "Opening " stores "Opening", and SwiftUI pushes "Opening" back into the field, dropping the space, so multi-word titles can only be pasted. Selecting all and deleting to retype stores `""`, and the getter immediately puts the original source title back mid-edit.
**Fix:** Edit a local draft and normalize only on commit or focus loss:
```swift
struct ChapterTitleField: View {
    let initial: String
    let commit: (String) -> Void
    @State private var draft = ""
    @FocusState private var focused: Bool
    var body: some View {
        TextField("Title", text: $draft)
            .focused($focused)
            .onAppear { draft = initial }
            .onChange(of: initial) { _, new in if !focused { draft = new } }
            .onSubmit { commit(draft) }
            .onChange(of: focused) { _, isFocused in if !isFocused { commit(draft) } }
    }
}
```
Alternatively, store the untrimmed text in the binding and trim only when building the output.

### CR-03: Languages fields re-format every keystroke, so only one language can be typed

**File:** `Sources/HyperVideoConverter/Views/Tabs/AudioBehaviorSection.swift:55-60`, `Sources/HyperVideoConverter/Views/Tabs/SubtitlesSettingsTab.swift:12-17`, `Sources/HyperVideoConverter/Stores/TrackListEditing.swift:6-13`
**Issue:** Both bindings run `get: LanguageList.format(...)` and `set: LanguageList.parse($0)`. Typing "eng," parses to `["eng"]`, which formats back to `"eng"`, so the comma disappears. Typing "eng " drops the space the same way. The separator never survives, so a second language can't be typed (only pasted). This blocks the "eng, por" input the placeholder suggests.
**Fix:** Same pattern as CR-02. Keep a `@State` draft string and call `LanguageList.parse` on submit or focus loss. Or keep the raw text in the model (`languagesText`) and derive the array from it.

## Warnings

### WR-01: StatusBanner literals are never localized

**File:** `Sources/HyperVideoConverter/Views/Tabs/DimensionsSettingsTab.swift:15`, `Sources/HyperVideoConverter/Views/Tabs/FiltersSettingsTab.swift:13`
**Issue:** `StatusBanner(messages: [String])` renders with `Label(message, systemImage:)`, the `StringProtocol` overload, which is verbatim. pt-BR has entries for "Passthrough copies the video as is…" and "Filters need the video to be re-encoded…", but they are never looked up. Other callers wrap the text in `String(localized:)` first (`VideoSettingsPanel.swift:55`).
**Fix:** `StatusBanner(messages: [String(localized: "Passthrough copies the video as is. Choose an encoder in Video to change its size.")])`. Better: make `StatusBanner` take `[LocalizedStringResource]`.

### WR-02: Before → After ignores the explicit subtitle/audio track lists and language filters

**File:** `Sources/HyperVideoConverter/Views/Tabs/BeforeAfterSection.swift:75-99`
**Issue:**
- `keptSubtitles` uses only `settings.subtitles` and the container. It ignores `subtitleOptions.tracks` (per-track Include) and `subtitleOptions.languages`, so unticking tracks in the Subtitles tab doesn't change the "After" count.
- `mainAudioOutput` ignores `audioOptions.tracks` when it holds exactly one track and shows the global codec and bitrate instead of that track's encoding. It also ignores `audioOptions.languages`.

The summary therefore disagrees with what the engine (`AudioTrackPlanner`, line 18) will produce.
**Fix:** Count `settings.materializedSubtitleTracks(info: info).filter(\.include)`, keeping only tracks whose kind is supported in the container. Use `tracks.count >= 1` and describe `tracks[0].encoding` when the list is explicit.

### WR-03: ForEach over `Array($settings.audioOptions.tracks.enumerated())` can crash on removal

**File:** `Sources/HyperVideoConverter/Views/Tabs/AudioSettingsTab.swift:50-54`
**Issue:** The element bindings come from the index-based `Binding<[T]>` collection. When a card is removed while its Name `TextField` is focused, the field commits on focus loss through a binding whose index no longer exists. This is the well-known "Index out of range" crash. The settings binding re-reads `sources` on every access, which widens the window.
**Fix:** Build an id-based binding per card:
```swift
ForEach(Array(settings.audioOptions.tracks.enumerated()), id: \.element.id) { index, track in
    AudioTrackCard(setting: Binding(
        get: { settings.audioOptions.tracks.first { $0.id == track.id } ?? track },
        set: { new in settings.audioOptions.tracks = settings.audioOptions.tracks.map { $0.id == track.id ? new : $0 } }
    ), number: index + 1, sources: info.audioTracks) { settings = settings.removingAudioTrack(track.id) }
}
```

### WR-04: Crop "Detect" runs an unstructured Task that can write another video's crop, and `isDetecting` can stay stuck

**File:** `Sources/HyperVideoConverter/Views/Tabs/CropSection.swift:57, 103-113`
**Issue:**
- The Detect button starts `Task { await detect() }`. That task is never cancelled, and the view identity survives a panel switch to another video, so a late result from video A lands in `detectedCrop` while video B is shown. `FinalDimensions` (DimensionsSettingsTab:88) then uses that crop.
- `detect()` returns on cancellation, or when the mode stops detecting, without resetting `isDetecting = false`.
- `detectedCrop` keeps the previous video's value until the new detection finishes.

**Fix:** Drive manual re-detection through the `.task(id:)` by adding a `@State var detectNonce` to the id. Set `detectedCrop = nil` at the start of each run, use `defer { isDetecting = false }`, and check that `info.url` still matches before assigning.

### WR-05: Two confirmation dialogs share one `confirmingApplyToAll` flag and can apply from the wrong source

**File:** `Sources/HyperVideoConverter/Views/Panel/VideoSettingsPanel.swift:72-79`, `Sources/HyperVideoConverter/Views/AdvancedSettingsSheet.swift:82-89`
**Issue:** The inline panel and the Advanced sheet can be on screen together: the panel for the selected video, the sheet opened from another row's context menu. Both attach `.confirmationDialog(isPresented: $ui.confirmingApplyToAll)`. Pressing "Apply to All" in either sets the same flag, so both dialogs may present. The panel's dialog calls `applyToAll(from:)` with the panel's `source.id`, not the sheet's.
**Fix:** Use view-local `@State private var confirmingApplyToAll = false` in each view. Or store the source id in the flag: `ui.applyToAllSourceID: UUID?`, and present only when it equals `source.id`.

### WR-06: Export failures are reported under "Chapters not imported"

**File:** `Sources/HyperVideoConverter/Views/Tabs/ChaptersSettingsTab.swift:29, 96`
**Issue:** `exportCSV` puts write errors into `importError`, so a failed export shows the alert title "Chapters not imported".
**Fix:** Use a separate `exportError` state with the title "Chapters not exported". Or store an enum `{ import(String), export(String) }` and pick the title from it.

### WR-07: "Apply to All" help and confirmation text understate what each video keeps

**File:** `Sources/HyperVideoConverter/Views/Panel/VideoSettingsPanel.swift:73`, `Sources/HyperVideoConverter/Views/AdvancedSettingsSheet.swift:83` (message from `AppModel+Mode.swift:109`)
**Issue:** `copyingAll` now also keeps each video's audio and subtitle track lists, chapter titles and title tag (`SettingsMerging.swift:56-66`). The UI still says "each keeps its own trim, crop and burned-in subtitle", so users who expect their track or chapter edits to be copied get no feedback that they weren't.
**Fix:** Update both strings, plus pt-BR: "…each keeps its own trim, crop, burned-in subtitle, track lists, chapter names and title."

### WR-08: Applying a preset resets encoder Speed even when the preset leaves it at the default

**File:** `Sources/HyperVideoConverter/Stores/SettingsMerging.swift:80-86`
**Issue:** `keepingAdvanced` keeps the current `frameRateMode`, `profile` and `level` when the template has defaults. It doesn't do this for `videoOptions.speed`, so a video set to "Faster" silently returns to `.balanced` whenever any preset is applied. This breaks the rule in the doc comment ("the advanced choices … that the preset leaves at their defaults").
**Fix:** `if video.speed == defaults.videoOptions.speed { settings.videoOptions.speed = current.videoOptions.speed }`. Add a unit test that loops over every `VideoEncoderOptions` field so new fields can't be missed.

### WR-09: Explicit audio track lists silently override profile and inspector audio changes

**File:** `Sources/HyperVideoConverter/Stores/SettingsMerging.swift:23-33, 56-66`; `Sources/HyperVideoConverter/Views/Tabs/AudioSettingsTab.swift:32`
**Issue:**
- When `audioOptions.tracks` is non-empty, `AudioTrackPlanner` uses each track's own encoding.
- `applyingProfile` and `adopting` both keep the per-video track list and only change `audioCodec`/`audioBitrateKbps`. So after the user adds tracks, choosing a quality profile still shows that profile as selected (`matchesProfile` succeeds), but the output audio doesn't change.
- The quick inspector's audio fields also have no effect.
- In the Audio tab, the main "Encoding" section is hidden in this state, with no hint why.

**Fix:** Either update every explicit track's encoding when a profile or preset changes the audio codec or bitrate. Or show a notice in the inspector and Summary ("Audio uses the Audio tab's track list") and exclude audio from `matchesProfile` in that case.

### WR-10: Chapter rows use `.accessibilityElement(children: .combine)` around an editable TextField

**File:** `Sources/HyperVideoConverter/Views/Tabs/ChaptersSettingsTab.swift:52`
**Issue:** Combining the row merges the number, start and duration labels and the title `TextField` into one element, so VoiceOver can't focus or edit the field. Every field is also labelled just "Title", with no chapter number.
**Fix:** Drop `.combine`. Use `.accessibilityElement(children: .contain)` on the row and add `.accessibilityLabel(Text("Chapter \(index + 1) title"))` to the TextField.

## Info

### IN-01: CSV decoding fallback is dead code and mis-decodes UTF-16

**File:** `Sources/HyperVideoConverter/Stores/ChapterEditing.swift:47`
**Issue:** `.isoLatin1` decoding never fails, so `?? ""` can't be reached. UTF-16 CSVs (Excel's "Unicode Text") are decoded as Latin-1 with NULs, and the user sees a confusing "Line 1 isn't number,title" error.
**Fix:** Check for a BOM first (`FF FE`/`FE FF` → `.utf16`), then try UTF-8, then Windows-1252 (`.windowsCP1252`).

### IN-02: Size guard trusts a missing `fileSize`

**File:** `Sources/HyperVideoConverter/Stores/ChapterEditing.swift:44-46`
**Issue:** When `fileSizeKey` is nil, the size counts as 0 and the guard passes. `Data(contentsOf:)` then reads the whole file before `ChapterCSV.parse` rejects it. The 1 MiB limit is also duplicated (`ChapterEditing.sizeLimit` and `ChapterCSV.sizeLimit`).
**Fix:** Treat nil as an error, or read with `FileHandle.read(upToCount: limit + 1)`. Expose one shared constant.

### IN-03: Video profile/level normalization lives in a view `onChange`

**File:** `Sources/HyperVideoConverter/Views/Tabs/VideoSettingsTab.swift:19-22`
**Issue:** The fix-up runs only while the Video tab is visible. It never runs when the codec is changed from the inspector, a profile or a preset. It also fires when the panel switches to a video with a different codec and writes into that video. The engine resolves the profile at output time, so the visible effect is small.
**Fix:** Move it into an `EncodeSettings.choosing(videoCodec:)` model method, used by every codec setter.

### IN-04: Crop text fields accept out-of-range values; 2.39:1 uses display size

**File:** `Sources/HyperVideoConverter/Views/Tabs/CropSection.swift:80-99`
**Issue:** The TextField accepts negative values or values above 4,000 (only the Stepper is bounded). The engine clamps them, so the UI shows values that aren't used. The 2.39:1 button computes bars from `displaySize`, which is wrong for anamorphic sources.
**Fix:** Clamp the values in a custom binding (`min(max(0, v), 4000)`), and compute the 2.39:1 bars in storage pixels.

### IN-05: Auto-crop is reflected in Final Dimensions but not in Before → After

**File:** `Sources/HyperVideoConverter/Views/Tabs/BeforeAfterSection.swift:47` vs `Sources/HyperVideoConverter/Stores/VideoTabLogic.swift:74-78`
**Issue:** The two tabs show different output resolutions when cropping is Automatic or Conservative.
**Fix:** Share one helper. Document that Summary excludes auto-crop, or pass the detected crop in.

### IN-06: Menu shortcut builds a Character from a multi-digit string

**File:** `Sources/HyperVideoConverter/App/HyperVideoConverterApp.swift:161-165`
**Issue:** `Character(String(index + 1))` traps if a tenth tab is ever added.
**Fix:** `if index < 9 { .keyboardShortcut(KeyEquivalent(Character("\(index + 1)")), ...) }`, or use `prefix(9)`.

### IN-07: Panel "Save as Preset" saves `inspectorSettings`, not `source.settings`

**File:** `Sources/HyperVideoConverter/Views/Panel/VideoSettingsPanel.swift:92-96`
**Issue:** The two are equal today, but only because the panel requires a single selection. The alert text also says "shown in the inspector".
**Fix:** Save `source.settings` and set `presetID` on `source.id` only.

### IN-08: Switching Quality mode discards the previous value

**File:** `Sources/HyperVideoConverter/Views/Tabs/QualitySection.swift:8-13`
**Issue:** Switching between Constant Quality and Average Bitrate always resets to 0.62 / 6,000 kbit/s, which are magic numbers.
**Fix:** Name the constants and remember the last value of each mode in `@State`.

### IN-09: Unlocalized pieces in track labels

**File:** `Sources/HyperVideoConverter/Views/Tabs/AudioTrackCard.swift:131-133`
**Issue:** `track.channelDescription` and "und" are shown raw. Elsewhere `channelDescription` is localized (`AudioSettingsTab.swift:78`).
**Fix:** Use `String(localized: String.LocalizationValue(track.channelDescription))`.

### IN-10: Hard-coded sample date and debug defaults hook

**File:** `Sources/HyperVideoConverter/Views/Tabs/TagsSettingsTab.swift:13`, `Sources/HyperVideoConverter/Stores/UIState.swift:19`
**Issue:**
- The Release Date prompt is a fixed date, "2026-10-22".
- `InitialSettingsTab` is read from `UserDefaults.standard`, so a stray persisted value also changes the start-up tab in release builds.

**Fix:**
- Use a format hint such as "YYYY-MM-DD".
- Read the screenshot hook from `ProcessInfo.processInfo.arguments`, or guard it with `#if DEBUG`.
