## Deviations from Plan

**1. [Rule 1 - Bug] 7.1 layout tag**: `kAudioChannelLayoutTag_MPEG_7_1_C` is rejected by the AAC encoder (`canApply` false, writer-input exception). `kAudioChannelLayoutTag_MPEG_7_1_B` (AAC 7.1) is accepted, so `channelLayoutData(channels: 8)` uses it; the test asserts 7_1_B.

**2. [Rule 1 - Bug] AAC bitrate limits depend on sample rate**: `canApply` accepts bitrates the encoder later fails on ("Cannot Encode Media"). Probing showed stereo limits (kbit/s): 8 kHz up to ~32, 16 kHz up to ~96, 22.05 kHz up to ~96, 32 kHz at least 64 but 32 fails. `clampedAACBitrate` now clamps per channel by sample-rate band (below 44.1 kHz) and uses a 320 kbit/s floor for 8 channels (160 fails). Default 48 kHz stereo/mono/5.1 values are unchanged.

**3. HE-AAC check**: MOV reports the base format `aac `; the HE signal is in the format list (`CMAudioFormatDescriptionGetFormatList`), so the test checks that. HE-AAC 8 channels falls back to 6 then 2 when `canApply` rejects it.

## Notes
- `selectedAudioTracks()` removed; source track IDs in explicit lists are the asset's real track IDs (video is usually 1, audio starts at 2 in test clips).
- The "unsupported writer setting throws cannotConfigure" path is implemented (retry without bitrate, then throw) but has no dedicated test since no setting combination reached it.
